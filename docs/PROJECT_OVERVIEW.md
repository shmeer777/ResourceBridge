# Project Overview

## Problem
Useful equipment, spaces, and technical resources often sit idle while other people and organisations need access to them.

## Core roles
- Provider: lists resources, defines availability and eligibility, and manages booking requests.
- Seeker: searches resources, requests bookings, and manages reservations.
- One account may eventually hold both roles; permissions must be enforced by the backend.

## Core workflow
1. Provider registers a resource.
2. Seeker searches and views resource rules.
3. Seeker requests an available time slot.
4. Provider approves or rejects the request.
5. The platform prevents overlapping reservations.
6. Parties check in/out and submit condition reports.
7. Important actions are recorded in an audit history.
